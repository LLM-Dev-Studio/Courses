# Before You Start

A Discovery Session needs two things ready before you open
[modeller.website](https://modeller.website).

## The Original Change Request

Keep the request in the words it arrived in. Do not tidy it into a problem
statement first.

> [!WARNING]
> "Build us a new approval system" is a perfectly good entry for the change
> request field. Resist the urge to rewrite it as a problem statement — the
> Initiative deliberately keeps the request and the problem separate, and
> Discover is where the problem gets clarified.

## A Domain Expert

You need someone who lives with the situation and can answer questions about
it. You will send this person a link once the Initiative exists.

## Your Own Role

You will facilitate the session: guiding it, deciding which questions to ask,
and accepting what becomes part of the record. You do not need the CLI, the
VS Code extension, or a model to run Discovery. Those tools belong to System
Design, which an Initiative only reaches if it selects a technology
intervention.

## Practical Steps

1. Write down the change request exactly as it was given to you.
2. Identify the Domain Expert you will invite.
3. Confirm you are ready to act as Facilitator for the session.

## Key Takeaway

Prepare the raw change request and identify your Domain Expert before you
open [modeller.website](https://modeller.website) — everything else happens
inside the session itself.
