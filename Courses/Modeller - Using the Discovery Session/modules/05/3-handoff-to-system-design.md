# Handoff to System Design

Not every Initiative reaches System Design. This lesson covers what happens
when one does.

## When the Handoff Happens

An Initiative reaches System Design only when it selects a technology
intervention that is marked to continue into a design workspace. Selecting a
technology intervention adds a cross-reference to that workspace.

> [!IMPORTANT]
> The link carries the reason for the design forward. It deliberately does
> not generate model content from the intervention wording — System Design
> starts from the Initiative's reasoning, not from an automatic translation
> of it.

## Non-Technology Interventions Are Legitimate Outcomes

Modeller does not assume every Initiative ends in software. A Process,
People, Policy, Information, Organisation, Experiment, or No action
intervention is a complete and legitimate outcome on its own. Treat a session
that never reaches System Design as a success if it selected the right
response for the situation.

## Where System Design Picks Up

If your Initiative does select a technology intervention that continues, the
[Quick start](https://modeller.wiki/docs/getting-started/quick-start) guide
covers installing the CLI, creating a definition, and generating a project.
You can also try [the playground](https://modeller.website/playground) to
explore System Design's modelling without an Initiative at all.

## Practical Steps

1. Confirm which interventions, if any, are marked to continue into a design
   workspace.
2. Follow the cross-reference from a continuing technology intervention into
   its System Design workspace.
3. Check that the reason for the design is visible from within that
   workspace.

## Key Takeaway

A technology intervention hands off to System Design with its reasoning
attached, but a Discovery Session that selects no technology intervention at
all is just as legitimate an outcome.
