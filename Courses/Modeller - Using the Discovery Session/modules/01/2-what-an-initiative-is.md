# What an Initiative Is

An Initiative is the record a Discovery Session builds. It starts with a
change request and grows into a structured account of the problem, the
outcomes, and the response.

## The Journey an Initiative Takes

An Initiative moves through three stages.

**Discover** establishes what is happening before anyone treats the request
as the answer:

1. Capture Request — keep the original change request, word for word.
2. Clarify Problem — describe the problem, the affected people, and the pain
   points.
3. Identify Impact — make the current impact and evidence visible.

**Frame** agrees what "better" means and where the Initiative is bounded:

4. Define Outcomes — record desired outcomes and success criteria.
5. Set Boundaries — record non-goals, constraints, assumptions, open
   questions, and risks.

**Shape** compares possible responses against the outcomes and constraints
from Frame, then selects one or more.

> [!IMPORTANT]
> The original change request is never rewritten or discarded. Discover keeps
> it separate from the problem statement so the team can compare what was
> asked for against what the situation actually needs.

## One Record, Not Several Documents

Discover, Frame, and Shape all update the same structured Initiative record.
There is no separate Business Problem Brief. If your organization needs a
human-readable document, treat it as a projection of the Initiative record —
not a second source of truth to keep in sync by hand.

## Key Takeaway

An Initiative is a single growing record that carries reasoning from the
original request through to a selected response — it is not a spec for the
first proposed solution.
